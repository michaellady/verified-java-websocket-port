# F005 — A stress test that bounds its owner loop by a poll count assumes the host's scheduling speed
phase: native-thread evidence (nearest: port-link / port-calibrate)   step: n/a   date: 2026-09-02T19:15Z
what happened: `racing_producers_never_lose_or_duplicate_commands` in `rust/ws-driver/tests/concurrency.rs` runs four producer threads enqueueing 50 commands each against one owner, and the owner's drain loop was bounded by `polls < POLL_BUDGET` with `POLL_BUDGET = 2_000_000`. Under three other agents' load on this host the producers had not finished enqueueing when the owner exhausted the count, the loop exited early, and `assert_eq!(applied.len(), TOTAL)` failed with `left: 179 right: 200`. The properties the test exists for (no accepted command lost, none applied twice, exact wire total, exactly-once terminal) were never violated; the failing assertion was a statement about the machine. Two sibling loops in the same file carried the same guard.
what it cost: one red `test-release` inside the post-failure landing, and the landing agent's time establishing that the crate under test had not changed; it then correctly declined to fix it inside that landing and recorded it as a follow-up.
where the deciding moment was: when the guard against a non-converging owner was written as a count of polls rather than a duration. This is F004's deciding moment verbatim, one crate over — and F002's before that. A count of loop iterations is a host-speed measurement dressed as a bound (REFERENCE section 4, first form, host variant).
evidence: `rust/ws-driver/tests/concurrency.rs` (the `POLL_DEADLINE` doc comment and the three loop guards that replaced `POLL_BUDGET`); six consecutive release runs of the suite green; `drafts/self-review/post-failure-landing.md`, where the landing agent recorded the failure and left the remedy.
bin: THIRD sighting of the class (F002 buffer size, F004 spin count, F005 poll budget). The rule has now been proposed twice and rediscovered twice, which is itself the finding: a portable rule that lives only in a findings file does not bind anything. **The generalisation to file against the family: no fixture's own liveness guard may be a count of operations; it is a generous wall-clock deadline, and any counter kept alongside it may only REPORT in the failure message, never decide.** A grep for `< [A-Z_]*BUDGET` / `< 4096`-style loop guards across `rust/**/tests/` would make the class detectable instead of rediscoverable, and nothing does that today.
