### US-003 — Create the independent and held-out verification lane
**Priority:** 1 | **Passes:** true | **Depends on:** US-001, US-002 | **Labels:** security, verification, pre-flight | **Worker:** ["security-scanner","dev-qa-tester","reality-checker"] | **Model hint:** 

As the program owner, I want protected, rotating verification cases executed independently from implementers so that apparent success cannot come from fitting every known test.

**Acceptance criteria:**
- The held-out threat model identifies who can read cases, who can trigger runs, what implementers receive, how leakage is detected, and how compromised cases are retired.
- Three language-independent corpus tiers are defined: public development cases, hidden validation cases, and sealed final cases; sealed execution denies model and agent network access and detects source execution, wrappers, JVM, JNI, FFI, source-binary reuse, test discovery, substitute implementations, and other declared evasion paths.
- Neutral public conformance suites remain visible and mandatory; hidden and sealed cases supplement rather than replace standards evidence, and corpus vectors cover valid acceptance, invalid single-defect rejection, differential behavior, roundtrip and metamorphic properties, shrunk property failures, fuzz artifacts, mutation escapes, and resolved production counterexamples.
- Every language-independent oracle is calibrated before use: the pinned Java implementation passes 100%, an empty or stub Rust target fails, planted Java and Rust mutants are killed, repeated runs reconcile every case, and any unexplained flake or excluded source/spec disagreement blocks acceptance.
- The private lane records immutable case-set versions, source provenance, run identity, implementation commit, toolchain, platform, exact executed/skipped counts, and signed or content-addressed result manifests.
- Implementers receive only a budgeted diagnostic after an independent run: level 0 exposes claim and category, level 1 exposes a bounded semantic class, and level 2 exposes an independently generated public analogue; raw cases, expected outputs, generators, and protected logs never become model-visible.
- Actor, snapshot, query, and information budgets are enforced across retries; repeated probing, transcript leakage, protected-case fingerprint matches, or unauthorized access raises a named privacy failure, invalidates affected evidence, quarantines the run, and triggers case rotation when compromise is possible.
- The evaluator runs in a separate trust zone with no filesystem, cache, credential, signing-key, or workspace sharing with implementers or untrusted build runners, and logical exactly-once query reservations prevent retries from consuming or revealing additional budget.
- At least one seeded failure proves the lane rejects a plausible overfit implementation, and a rotation drill replaces the exposed case without changing historical evidence.
- Access and credentials use HQ-native grants and secrets; no protected case, token, or expected output enters a public repo, prompt transcript, or CI log.

**E2E tests:**
- Given a correct fixture and an overfit fixture, when the independent lane runs the same hidden case-set version, then the correct fixture passes, the overfit fixture fails, neither run reveals protected expected outputs, and both evidence manifests reconcile every case exactly once.
