### US-020 — Define Java intake, compatibility, and production-cutover contracts
**Priority:** 1 | **Passes:** true | **Depends on:** US-001, US-002 | **Labels:** foundation, java-intake, cutover, pre-flight | **Worker:** ["architect","dev-qa-tester","performance-benchmarker","security-scanner"] | **Model hint:** 

As a Java system owner, I want the actual import surface and replacement boundary qualified before translation so that a verified Rust port can become a safe, target-scoped production cutover rather than an isolated laboratory success.

**Acceptance criteria:**
- A versioned JavaIntakeManifest captures the authoritative project JDK and Maven or Gradle build, modules, source sets, generated sources, annotation processors, dependencies, features and profiles, native libraries, reflection, dynamic class loading, agents, JNI, serialization, persistence, concurrency, time and randomness, filesystem and network effects, framework lifecycle, resource files, deployment topology, and existing test and observability surfaces.
- The intake reconciles static inventory, pinned JDK compiler and build output, test discovery, runtime tracing, and JDT LS navigation; JDT LS disagreement is recorded as DeveloperToolRun evidence and never overrides the actual build.
- A Port Seam Dossier enumerates public APIs and Java consumers, semantic IDs, serialization, wire and file formats, ownership, threads and executors, reflection and generated code, native calls, global state, compatibility adapters, pointer or handle and lifetime obligations where applicable, touched-file set, and a bounded seam budget before implementation.
- A CompatibilitySurface maps every in-scope public, wire, file, database, state, error, timing, resource, and operational behavior to an oracle and evidence obligation; nil, empty, malformed, oversized, duplicate, interrupted, stale, and upstream-error paths are explicit.
- A Behavior Delta Ledger classifies every Java/Rust/spec disagreement as preserve, intentionally-correct with authoritative before-and-after evidence, or unresolved; unresolved deltas block completion and a refutation or later pass never erases the original finding or adjudication history.
- A CutoverContract declares the exact consumer-visible replacement boundary, state and data compatibility, side-effect policy, observability, SLO and capacity envelope, shadow and canary method, rollback window, reconciliation path, and every excluded or unresolved behavior.
- The readiness ladder is SOURCE_QUALIFIED, SEMANTICALLY_VERIFIED, OPERATIONALLY_VERIFIED, SHADOW_VERIFIED, CANARY_VERIFIED, and CUTOVER_READY; no state may be skipped, and CUTOVER_READY is bound to one Program Snapshot, integration boundary, platform profile, and production-shaped environment.
- The pinned Java executable remains runnable as an out-of-process oracle and rollback target until an explicit independently attested removal decision follows all differential, sealed, mutation, safety, formal, performance, shadow, canary, soak, and rollback gates; source removal or test deletion cannot substitute for that decision.
- Unsupported or unobservable dynamic behavior produces CompatibilitySurfaceIncomplete or UnsupportedDynamicFeature, lowers the assurance ceiling or blocks planning, and is never inferred away from a green build or test run.
- A miniature service fixture and a miniature library fixture prove that the intake detects seeded reflection, serialization, annotation-processing, native, state-migration, side-effect, and rollback hazards before a child PRD is accepted.
