# java-semantic-oracle

Emits **compiler-derived** semantic identities for the pinned Java-WebSocket source tree.

Identity comes from javac's own symbol table — `javax.lang.model` elements read after
`com.sun.source.util.JavacTask.analyze()` — not from text or grep matching. US-003 records
static/grep lookup as strictly weaker than compiler/LSP semantic identity and unable to establish
a proved claim, so this tool is the only permitted source of Java identity in
`evidence/intake/semantic-id-migration-map.json`.

For each declaration it emits the fully-qualified binary name, the JVM descriptor, the generic
signature, modifiers, and the source file and line. For each file it emits the physical line count
(newline bytes, matching `wc -l` exactly) and the sha256 of the exact source bytes.

## Quarantine posture

The analyzed tree is a quarantined input. The tool **parses and attributes** it and never runs it:

- annotation processing is disabled with `-proc:none`, so no code from the target tree executes
- no target class is loaded, instantiated, or invoked
- the upstream build is never invoked

## Inputs

| Input | Provenance |
| --- | --- |
| Java-WebSocket source archive | `evidence/intake/source-pins.json` → `java-websocket-source-archive`, sha256 verified before use |
| `org.slf4j:slf4j-api:2.0.13` | version read from the digest-pinned upstream `pom.xml`; the sole non-JDK compile dependency, needed only so javac can resolve the logging imports in `WebSocketImpl` and `Draft_6455`. Its sha256 must equal the US-002-qualified digest (`internal/lab/autobahn_endpoint.go`, `AutobahnSLF4JAPIDigest`); the Makefile `require-inputs` gate verifies this before javac runs and fails closed on mismatch |
| OpenJDK 17.0.19 | `openjdk-17.0.19-homebrew-bottle` in the pinned toolchain |
| `study-surface.txt` | generated by `portplanctl study-surface`, which applies the AC2 selection rule |

## Reproducing

Re-acquire the pinned archive and verify its digest before use:

```sh
curl -sSL -o archive.tar.gz \
  https://github.com/TooTallNate/Java-WebSocket/archive/da3cf2a777aed862f2f5b5cf060cae7969958667.tar.gz
shasum -a 256 archive.tar.gz
# must equal f44e7647b4aee40819b51947cf0bb5f35a48293a202b77704c3c79e98ed13cb4
tar -xzf archive.tar.gz -C .quarantine
```

Regenerate the study-surface list from the selection rule, then run the oracle:

```sh
go run ./cmd/portplanctl study-surface \
  --source-root .quarantine/Java-WebSocket-<commit>/src/main/java \
  --out java-semantic-oracle/study-surface.txt

make -C java-semantic-oracle run \
  JAVA_SOURCE_ROOT=../.quarantine/Java-WebSocket-<commit>/src/main/java \
  SLF4J_API_JAR=../.quarantine/slf4j-api-2.0.13.jar
```

Then rebuild the frozen intake documents and verify them:

```sh
go run ./cmd/portplanctl derive --root . \
  --production-root .quarantine/Java-WebSocket-<commit>/src/main/java \
  --test-root .quarantine/Java-WebSocket-<commit>/src/test/java \
  --oracle java-semantic-oracle/build/semantic-ids.json \
  --oracle-tool java-semantic-oracle/src/main/java/SemanticIdOracle.java \
  --source-sha256 sha256:f44e7647... --source-commit da3cf2a7... --rfc6455-sha256 sha256:76577532...

go run ./cmd/portplanctl verify --root .
```

The oracle report is committed at `evidence/intake/semantic-id-oracle.json` (the Makefile's
default `OUTPUT`). `portplanctl derive` refuses to run unless every file entry in that report —
path, sha256, and physical line count — matches the materialized tree exactly
(`ORACLE_TREE_MISMATCH` otherwise). `go test ./internal/portplan/` re-derives the six documents
and requires byte-identical output; when the quarantined source is absent it re-acquires the
pinned archive over the network, digest-verifies it, and FAILS with a typed reason if that is
impossible. It never skips.

## Expected output on the pinned tree

```
files=78 physical_lines=12317
study_files=52 study_physical_lines=6916
declarations=969 errors=0 analyzed_top_level=67
```

`errors=0` is required: a non-zero compiler error count means identities were not fully resolved,
and the deriver refuses such a run. The 11-file gap between 78 files and 67 analyzed top-level
types is exactly the 11 `package-info.java` documentation units, which declare no type.
